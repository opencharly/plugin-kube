# 2026.276.0815 — fix(kube): fail loudly when a vm deploy's port-forward entity cannot resolve [carry-forward of #13/#9]

## Summary

`deployVMForwards` (`candy/plugin-kube/k3s_post.go`) silently swallowed **two** failures on the k3s post-provision path:

- the project-dir resolve — `dir, _ := hostProjectDir(ctx, exec, deployName)` (error discarded);
- the `kind:vm` entity resolve — `if verr != nil || vmPtr == nil { return nil, nil }` (`//nolint:nilerr // best-effort`).

With zero forwards, `rewriteK3sServerToForward` no-ops on its own `len(forwards)==0` branch, and the raw kubeconfig — still pointing at the **guest-local `127.0.0.1:6443`** — is merged as a **dead context, with no error**. Every `kube:` / `kubevirt:` probe against that deploy then fails `no kubeconfig context selected`.

Reaching the entity resolve already means `vmEntity != ""` (the non-VM case returns early above), so a nil/err there is a **real failure**, not a best-effort miss. Both are now returned with context, and the nil case **refuses to merge a guest-local kubeconfig**.
