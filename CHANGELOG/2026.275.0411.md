## Summary

Bump `spec`/`sdk` past the schema gate that was degrading every `deploy:kubernetes` / `deploy:kindcluster` bed's deploy key, and sweep the removed `spec.Deploy.Version` field (R5). Fixes the producer leg of `opencharly/charly#738`.

## RCA

Every `deploy:kindcluster` bed fails at its `deploy-add` step:

```
charly: error: command "deploy": deploy-dispatch add: deploy plugin:
  deploy-dispatch add: preresolve substrate "kindcluster":
  InvokeProvider deploy:kindcluster op=preresolve: rpc error:
  code = Unknown desc = deploy "check-kindcluster-workload":
  resolving kindcluster "check-kindcluster-cluster":
  <project>/charly.yml: schema 2026.261.1747 is required (found "").
  Run: charly migrate
```

Root cause: the schema-versioning-removal cutover deleted the load-time schema gate in `sdk v0.2026270.1147`. This plugin self-loads the project config, and its newest release still compiled against `sdk v0.2026268.1823`, so the retired gate rejected the current (unversioned) config and degraded the deploy key. This is the `charly#733` cutover reaching this repo: the gate is being retired, and a stale build must be re-pinned.
