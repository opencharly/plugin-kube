# 2026.318.0341 — refactor(kube): read the kindcluster body through the plugin's own view

## Summary

`opencharly/spec#304` unit 5, a consumer leg. The authored `#Kubernetes` and `#Kindcluster` bodies — and the Go types generated from them — move into the plugin that **serves** the kinds (`opencharly/plugin-substrate#35`, merged), so this plugin can no longer decode a kindcluster template into `spec.Kindcluster` nor build a `spec.Kubernetes` for the Kustomize projection.

**The wire was already opaque.** The template body arrives as raw JSON (`loaderkit.LoadUnifiedViaExecutor` → `ProjectTemplates().ByKind("kindcluster")`), and the generate request's `ClusterJSON` is a bytes field (`Cutover K`). So only the SHAPES this plugin reads and writes need a home:

- **`kindclusterspec.go`** (new): this plugin's view of the kindcluster body (identity + policy sub-blocks + the kind topology `engine`/`node_image`/`nodes`), and `kubernetesPolicy` — the projection target, with the authored JSON tags.
- **`kindcluster.go`**: `resolveKindclusterTemplate` decodes into the view, `renderKindClusterConfig` reads it, and the projection's call site notes that the body travels as `ClusterJSON`.
- **The fixtures** seed the view instead of the authored type.

### The resolver's own path — the test it needed and did not have

Round 1's review was right: every earlier test constructed the view in Go or tested the egress, so **the decode itself never executed**. `TestKindclusterSpec_DecodesAuthoredBody` now decodes a REPRESENTATIVE body — every field the plugin reads populated — through the same `json.Unmarshal` the resolver performs, asserts each value lands on its field, and then proves the decoded view **drives both consumers** (the kind-config renderer and the Kustomize projection). A view tag that diverges from the authored schema now fails the suite instead of silently dropping data.

**The property that makes "the body moved, the behaviour did not" checkable**: the projection's wire is pinned byte for byte.
