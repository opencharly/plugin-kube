# 2026.288.1548 — fix(kube): the verb's cluster connection — the template's kubeconfig file, the shared resolver, and the caller's deadline

## Summary

Makes the `kube:` verb's **cluster connection** correct, in three parts that are one story — how this
verb finds a cluster, reaches it, and behaves when it cannot.

1. **The cluster template's kubeconfig FILE now reaches the client, not only its context.** The contract
   (`spec#221`/`#224`) and the shared resolver (`sdk#376`, `v0.2026287.726`) already carry it; this plugin
   still consumed only the context, so a template whose context lives in its own file resolved to
   nothing. `preresolve.go` carries the file through, and the local copy of the resolver is
   **deleted** in favour of `loaderkit.ResolveClusterViaExecutor` — which is also the direction of
   `plugin-kube#21`, superseded by this PR (see below).

2. **The verb honours its caller's deadline.** `Invoke(ctx, …)` has always RECEIVED the host's RPC
   deadline and always dropped it: **20 client call sites passed `context.TODO()`**, an uncancellable,
   deadline-free context. A hung dial therefore outlived the host's deadline, kept the plugin blocked on a
   call nothing could cancel, and reported only `verb "kube": rpc error: code = DeadlineExceeded` — a gRPC
   status, which is how we know the HOST cancelled it while the plugin could not even name the phase that
   hung. `dispatch` now bounds the whole op by its own timeout — one canonical `opTimeout(method, op)` whose
   per-method defaults live in a single `methodTimeouts` table — nested inside the caller's deadline so the
   shorter wins, and threads it into all 13 methods plus the addons helper. The client is injectable through a `clientFunc` seam on
   the connection, so what the verb hands its client is observable in a unit test at all. **Every** deadline in the
   plugin now routes through that one helper: `grep -c 'parseTimeout(' methods.go` is `0`, and the four
   waiting methods call `opTimeout("<its own method>", op)` while the helper keeps their defaults exactly
   as they were (`lb-external-ip` 60s, `addons` 180s, the rest 120s).

3. **An errcheck sweep in the same candy.** `kindcluster.go` and `kind_load_image_test.go` stop
   discarding unchecked errors (`defer os.Remove` → `defer func() { _ = os.Remove(…) }()`, and the same for
   `cfgFile.Close()`, the archive defer and the test's handles). This is the QUAL half of the same
   cutover: those were the findings `golangci-lint` reported in this module, and they are fixed rather
   than filed.

4. **The dependency bump those two need**, `sdk v0.2026273.207 → v0.2026287.726` and
   `spec v0.2026273.203 → v0.2026287.716`. **Intent, per Part II #3:** these are the *consumer* edge of a
   producer-first sequence — `spec#221`/`#224` and `sdk#376` are merged and TAGGED upstream, and this PR
   adopts exactly those merged tags rather than any branch. There is no unmerged producer leg this pin
   waits on. `go list -m github.com/opencharly/spec` selects **v0.2026287.716**, the tag adopted above;
   `go.sum` additionally carried a stale `spec v0.2026287.727` checksum that NO module in the graph
   requires, so `go mod tidy` pruned it here rather than leaving a version named nowhere.

**Supersedes `opencharly/plugin-kube#21`** (`feat/c9-cluster-resolver-consumer`), whose direction this
branch contains and extends: its resolver delegation is here, plus the kubeconfig file it did not carry.
Its own week-old BLOCK findings are answered here — the runtime beds its review demanded are below, by
name. Ownership was taken over comment-first after its author had been silent for two days.
