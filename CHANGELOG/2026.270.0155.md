# 2026.270.0155 — fix(kindcluster): save the workload image to a real file, not `podman save -o -`

## Summary

`kindLoadImage` piped `podman save -o - <image>` into `kind load image-archive`. On the
podman versions charly supports, `-o -` does **not** mean stdout — it writes a FILE
named `-` in the cwd (measured on podman 6.1.2: a 330 MB file `./-`, stdout EMPTY). The
provider then loaded an empty archive into the kind node and `ctr images import` failed:

```
ERROR: failed to load image: command "podman exec --privileged -i
check-kindcluster-workload-control-plane ctr --namespace=k8s.io images import
--all-platforms --digests --snapshotter=overlayfs -" failed with error: exit status 1
Command Output: ctr: unrecognized image format
```

**Fix:** extract `kindSaveImageArchive(provider, imageRef, dest)` — the exact call
`kindLoadImage` makes — and have it run `podman save -o <dest> <image>` (a real path);
`podman save -o <file>` emits the docker-archive tar (`manifest.json`), the format
`ctr images import` accepts.
