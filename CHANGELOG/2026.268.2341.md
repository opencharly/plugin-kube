## Summary of changes

Add `deploy:kindcluster` — a local Kubernetes-in-Docker cluster provisioned by the
upstream **kind** tool (kubernetes-sigs/kind) on the operator's container engine —

kind-integration cutover; the spec leg merged as `opencharly/spec#162`.

### Design notes

- **Engine selection is free.** kind's provider selector is exactly charly's
  engine vocabulary (`podman`/`docker`/`nerdctl`), so the deploy's `engine:` /
  the resolved `engine.run` maps 1:1 to `KIND_EXPERIMENTAL_PROVIDER`.
- **No per-kind sdk leg.** The template resolves via the generic exported
  `loaderkit.LoadUnifiedViaExecutor` + `ProjectTemplates().ByKind("kindcluster")`.
- **One policy surface (R3).** The kindcluster policy is projected onto a
  `#Kubernetes` body so the workload generation reuses `materializeKustomize`.
- **Engine-aware image load.** `kind load docker-image` is measured BROKEN on
  podman; `kind load image-archive` works on every engine, so the provider saves
  the image and loads the archive.
- **Teardown** is `kind delete cluster` + tree removal, recorded as a ReverseOp.

the engine-unscoped teardown (left the cluster behind); and the config-as-JSON
