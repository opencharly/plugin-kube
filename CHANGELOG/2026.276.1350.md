# 2026.276.1350 — fix(kube): fail loudly when a kube: verb's named cluster: cannot resolve (the #15 verb half)

## Summary

`provider.go`'s `kube:` check-verb resolution swallowed **both** its error paths — the `hostProjectDir` resolve and the `kind:kubernetes` entity resolve. A `kube:` step that NAMED a cluster (`cluster: <profile>`) whose resolution failed therefore silently left `KubeContext == ""`, and `connFromInput` fell back to the kubeconfig `current-context` — which was `""` on the bed — so the probe died with the bare `no kubeconfig context selected`, hiding the cause.

Rework: the resolve is extracted into `resolveKubeVerbCluster` (with a package-var test seam), which **returns** its errors; the verb **fails loudly** naming the cluster and the cause. The legitimate-miss case — the profile resolves but carries no context — still returns `("", nil)`, so the caller keeps its `current-context` fallback.

This is the `kube:` **VERB** half of `opencharly/plugin-kube#15`; the k3s post-provision half was fixed in **`#16`** (merged, `v2026.276.0815`).
